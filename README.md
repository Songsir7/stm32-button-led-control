# stm32-button-led-control

基于 STM32F103C8T6 的按键控制 LED 入门示例项目。

当前分支为：

```text
v1.0-buggy
```

该分支用于记录项目最初版本中出现的按键控制 Bug，方便后续与修复版本进行对比学习。

---

## 一、实验目标

本版本原计划实现两个独立按键分别控制两个 LED 的功能。

预期效果如下：

```text
按住 PA8，LEDA0 亮
松开 PA8，LEDA0 灭

按住 PA11，LEDC14 亮
松开 PA11，LEDC14 灭

两个按键同时按下时，两个 LED 都亮
松开其中任意一个按键时，只熄灭对应的 LED
```

---

## 二、硬件连接说明

本次实验使用 STM32F103 系列单片机。

按键连接如下：

```text
PA8  接一个按键，上拉输入，低电平表示按下
PA11 接一个按键，上拉输入，低电平表示按下
```

LED 控制关系如下：

```text
PA8  按下时，控制 LEDA0
PA11 按下时，控制 LEDC14
```

---

## 三、实际 Bug 现象

实际测试时发现，两个按键没有真正做到独立检测。

异常现象如下：

```text
先按下 PA8 不松手，
再按下 PA11，
LEDC14 不会亮。
```

也就是说，当 PA8 已经被按下时，PA11 的按键状态无法被正常识别。

反过来测试时，又会出现不同表现：

```text
先按下 PA11 不松手，
再按下 PA8，
LEDC14 可以保持亮。
```

这个现象说明：  
当前程序并没有真正同时记录两个按键的状态，而是存在按键判断优先级和状态覆盖问题。

---

## 四、问题代码说明

### `Key_GetNum()` 原始逻辑

当前版本的 `Key_GetNum()` 使用了类似下面的判断方式：

```c
if(GPIO_ReadInputDataBit(GPIOA, GPIO_Pin_8) == 0)
{
    KeyNum = 1;
}
else if(GPIO_ReadInputDataBit(GPIOA, GPIO_Pin_11) == 0)
{
    KeyNum = 2;
}
else if(GPIO_ReadInputDataBit(GPIOA, GPIO_Pin_8) == 1 |
        GPIO_ReadInputDataBit(GPIOA, GPIO_Pin_11) == 1)
{
    KeyNum = 0;
}
```

这段代码的问题是：

```text
PA8 的判断在最前面。
只要 PA8 被按下，程序就会直接返回 KeyNum = 1。
后面的 PA11 判断不会继续执行。
```

因此，当 PA8 和 PA11 同时按下时，虽然两个引脚都处于低电平：

```text
PA8  = 0
PA11 = 0
```

但是程序只会识别到 PA8，返回：

```text
KeyNum = 1
```

不会返回 PA11 的状态。

---

## 五、主函数中的问题

原始 `main.c` 中多次调用了 `Key_GetNum()`：

```c
if(Key_GetNum() == 1)
{
    LEDA0_ON();
}

if(Key_GetNum() == 2)
{
    LEDC14_ON();
}

if(Key_GetNum() == 0)
{
    LEDA0_OFF();
    LEDC14_OFF();
}
```

这样写的问题是：  
每一个 `if` 都会重新读取一次按键状态。

也就是说，三个判断并不是基于同一次按键检测结果，而是分别调用了三次 `Key_GetNum()`。

更合理的写法应该是：

```c
KeyNum = Key_GetNum();
```

先读取一次按键状态，然后后面的判断都使用这一次读取到的 `KeyNum`。

---

## 六、Bug 原因总结

本次 Bug 的核心原因主要有三个。

### 1. 使用了 `if ... else if ... else if ...`

这种结构会导致多个按键被当成“互斥选择”处理。

当 PA8 已经满足条件时，PA11 的判断就不会执行。

因此程序无法同时记录两个按键的状态。

---

### 2. `Key_GetNum()` 只能返回一个按键编号

原始设计中：

```text
KeyNum = 1 表示 PA8 按下
KeyNum = 2 表示 PA11 按下
KeyNum = 0 表示没有按键按下
```

这种设计只能表示一个状态，不能同时表示两个按键都被按下。

所以当 PA8 和 PA11 同时按下时，程序无法返回“两个按键都按下”的结果。

---

### 3. 主函数中重复调用 `Key_GetNum()`

主函数中多次调用 `Key_GetNum()`，会导致每次判断都重新读取按键状态。

这样容易造成逻辑混乱，也不利于后续扩展多个按键。

---

## 七、修复思路

后续版本需要把多个按键状态改成“按位记录”。

例如：

```text
KeyNum 第 0 位表示 PA8
KeyNum 第 1 位表示 PA11
```

返回值含义如下：

```text
KeyNum = 0，二进制 0000 0000，表示两个按键都没有按下
KeyNum = 1，二进制 0000 0001，表示 PA8 按下
KeyNum = 2，二进制 0000 0010，表示 PA11 按下
KeyNum = 3，二进制 0000 0011，表示 PA8 和 PA11 同时按下
```

这样每个按键都占用一个二进制位，多个按键之间就不会互相覆盖。

---

## 八、修复后的判断方式

修复后，主函数中应该先读取一次按键状态：

```c
KeyNum = Key_GetNum();
```

然后通过按位与判断某个按键是否按下：

```c
if(KeyNum & 0x01)
{
    LEDA0_ON();
}
else
{
    LEDA0_OFF();
}

if(KeyNum & 0x02)
{
    LEDC14_ON();
}
else
{
    LEDC14_OFF();
}
```

这种写法可以让两个按键互不影响。

## 九、版本说明

当前分支，保留最初存在问题的版本。

主要问题：

- 两个按键无法真正独立检测
- `if ... else if` 导致按键判断有优先级
- `Key_GetNum()` 只能返回单一按键编号

---

后续修复版本。

主要修复方向：

- 使用按位记录方式保存多个按键状态
- `Key_GetNum()` 可以同时返回多个按键状态
- 主函数中每轮循环只调用一次 `Key_GetNum()`
- 使用 `KeyNum & 0x01` 判断 PA8
- 使用 `KeyNum & 0x02` 判断 PA11
- 实现两个按键独立控制两个 LED

## 十、学习意义

这个 Bug 很适合作为 STM32 入门阶段的学习记录。

通过这个问题可以理解：

- 多按键检测不能简单使用互斥判断
- `if ... else if` 会导致后面的按键状态被跳过
- 多个按键状态适合使用二进制位记录
- 主函数中应该尽量避免重复读取同一个输入状态
- 先保存状态，再根据状态执行控制逻辑，代码会更清晰

---

## 十一、最终结论

本版本的问题本质是：

```text
原程序把多个按键当成互斥选择来处理，
导致同一时间只能识别一个按键。
```

后续版本通过“按位记录”的方式，让每一个按键占用一个独立的二进制位，从而可以同时记录多个按键状态，解决两个按键不能同时独立控制 LED 的问题。
